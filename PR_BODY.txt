## Обзор
Консолидированный PR, объединяющий 5 улучшений:
1) Stats FS safety
2) Search helpers hardening
3) Prometheus hardening
4) AI offline-by-default
5) Deploy commands UX

Цель — повысить устойчивость и DX, без изменения публичного API команд.

## 1) Stats FS safety
- Debounce сохранения статистики (≈250 мс)
- Атомарная запись stats.json (.tmp + rename)
- Корректная сериализация Set ↔ Array (commands.users, dailyStats.users)
- Инициализация dailyStats в trackError (исправляет NPE)
- Место хранения: data/logs/stats.json

Tests:
- helpers/stats/__tests__/stats.test.ts — PASS (запись/log-dir, сериализация Set, init ошибок)

## 2) Search helpers hardening
- parseLocaleNumber: корректная сортировка чисел для локалей (“1 234,56”)
- truncateEmbed: защита от лимитов Discord (описание ~3800 символов)
- fetchWithTimeout: таймаут 10s + простые ретраи
- Кэш: MAX_CACHE_ENTRIES=100 + эвикция
- Безопасная индексация process.env и строк таблицы

Tests:
- helpers/search/__tests__/searchHelpers.test.ts — PASS (локальная сортировка)

## 3) Prometheus hardening
- try/catch вокруг inc/observe (исключения метрик не валят процесс)
- Gauges: CPU user/system (микросекунды), mem_free/total
- Простой rate-limit для /metrics (5 запросов/10с/на IP)
- ENV-конфиг без TS-импорта в JS (METRICS_ENABLED, METRICS_PORT, METRICS_PATH)

Tests:
- helpers/metrics/__tests__/prometheus.test.js — PASS (smoke: инкременты/observe/gauges не бросают)

## 4) AI offline-by-default
- По умолчанию офлайн-режим (AI выключен, если нет OPENAI_API_KEY или AI_PROVIDER='disabled')
- Ленивая инициализация OpenAI (getOpenAI) только при включённом AI
- extractJson: устойчивый парсер (поддержка fenced ```json ... ```)
- Безопасные офлайн-ветки в:
  - analyzeData
  - naturalLanguageSearch
  - generateRecommendations
  - generateSmartReport

Tests:
- helpers/ai/__tests__/aiHelpers.test.ts — PASS (4 теста офлайн-веток)

## 5) Deploy commands UX
- CLI-флаги для скрипта регистрации команд:
  - --dry: безопасный dry-run (ничего не публикует)
  - --mode=global|guild|both (по умолчанию both)
  - --guild=<id>: переопределяет guildId из конфигурации
- Маскирование guildId в логах (безопасные логи)

Tests:
- src/scripts/__tests__/deployCommands.test.ts — PASS (контракт parseArgs)

## Совместимость и раскатка
- Обратная совместимость сохранена; улучшения — безопасные
- Для метрик можно управлять через ENV:
  - METRICS_ENABLED (true/false), METRICS_PORT (по умолчанию 9091), METRICS_PATH (/metrics)
- Для AI включение по желанию:
  - OPENAI_API_KEY, AI_PROVIDER!='disabled'
- Регистрация команд:
  - Пример: ts-node src/scripts/deployCommands.ts --dry --mode=guild --guild=123...

## Риски и откат
- Низкие, все изменения сопровождаются юнит-тестами
- При необходимости:
  - Stats: вернуть прямое сохранение
  - Search: переключиться обратно на parseFloat
  - Metrics: ослабить/отключить rate-limit
  - AI: включить AI переменными ENV
  - Deploy: не использовать новые флаги (поведение по умолчанию «both»)
