# 🛡️ Безпека
# Посібник з безпеки Discord AI Assistant Bot

## 🔐 Загальні принципи безпеки

Discord AI Assistant Bot реалізує багаторівневу систему безпеки для захисту даних та запобігання зловживанням:

### 1. Контроль доступу
- Система ролей Discord
- Валідація прав доступу для кожної команди
- Контроль доступу до документів Google

### 2. Шифрування
- Усі дані передаються зашифровано
- API ключі зберігаються в змінних середовища
- Конфіденційні дані маскуються у логах

### 3. Моніторинг
- Логування всіх операцій
- Сповіщення про підозрілу активність
- Аудит дій користувачів

## 🛡️ Ролі та права доступу

### Система ролей Discord

Бот використовує наступні ролі для контролю доступу:

1. **Адміністратор** - повний доступ до всіх функцій
2. **Бот-Користувач** - базові команди
3. **Sheets-Доступ** - робота з Google Sheets
4. **AI-Доступ** - AI функції
5. **Експорт-Доступ** - експорт даних

### Налаштування ролей

Адміністратор сервера повинен:

1. Створити відповідні ролі у Discord
2. Налаштувати права доступу до каналів
3. Призначити ролі користувачам

## 🔒 Захист даних

### Конфіденційна інформація

Бот автоматично маскує конфіденційну інформацію:

- **Email адреси**: `user***@***.com`
- **Номери телефонів**: `+380 *** **** 123`
- **API ключі**: не зберігаються у логах

### Шифрування

- Усі з'єднання використовують HTTPS/TLS
- API ключі зберігаються лише у змінних середовища
- Дані в кеші (Redis) можуть бути зашифровані

## 🚦 Rate Limiting

Бот реалізує систему обмеження запитів для запобігання зловживанням:

### Ліміти запитів

- **Пошук**: 10 запитів за хвилину
- **AI аналіз**: 5 запитів за 2 хвилини
- **Експорт**: 3 запити за 5 хвилин
- **Загальні команди**: 20 запитів за хвилину

### Обхід лімітів

При перевищенні лімітів:
1. Користувач отримує повідомлення про обмеження
2. Подальші запити ігноруються до закінчення періоду
3. Адміністратор отримує сповіщення про повторні спроби

## 🧪 Валідація даних

### Перевірка вхідних даних

Всі вхідні дані проходять валідацію:

1. **Довжина**:
   - Пошукові запити: макс. 200 символів
   - AI запити: макс. 1000 символів
   - Назви файлів: макс. 100 символів
   - Загальний текст: макс. 500 символів

2. **Формат**:
   - Дати: формат ДД.ММ.РРРР
   - Числа: тільки цифри та десяткові розділювачі
   - Email: валідація формату

3. **Заборонені символи**:
   - HTML теги
   - SQL ін'єкції
   - Спеціальні символи системних команд

## 📊 Моніторинг безпеки

### Логування

Бот веде детальне логування всіх операцій:

1. **Події безпеки**:
   - Відмовлено в доступі
   - Перевищено ліміт запитів
   - Невалідні вхідні дані
   - Порушення безпеки

2. **Використання**:
   - Виконані команди
   - Оброблені AI запити
   - Доступ до файлів

### Формат логів

Логи містять наступну інформацію:
```
[РІВЕНЬ] [ДАТА] [ID_КОРИСТУВАЧА] [ID_КАНАЛУ] ПОВІДОМЛЕННЯ
```

Приклад:
```
[INFO] [2025-01-15 14:30:25] [123456789] [987654321] Виконано команду /пошук
```

## ⚠️ Реагування на інциденти

### Типи інцидентів

1. **Критичні**:
   - Неавторизований доступ до адміністративних функцій
   - Масові спроби обходу rate limiting
   - Підозріла активність з AI функціями

2. **Середні**:
   - Перевищення лімітів запитів
   - Невалідні вхідні дані
   - Помилки автентифікації

3. **Низькі**:
   - Невдалі спроби входу
   - Запити з підозрілих IP адрес
   - Незвичайна активність

### План реагування

1. **Виявлення**:
   - Моніторинг логів та метрик
   - Аналіз патернів активності

2. **Оцінка**:
   - Визначення рівня загрози
   - Оцінка потенційного впливу

3. **Реагування**:
   - Блокування користувача/функції
   - Сповіщення адміністраторів
   - Збір доказів

4. **Аналіз**:
   - Дослідження причин інциденту
   - Визначення вразливостей

5. **Відновлення**:
   - Повернення функціональності
   - Виправлення виявлених вразливостей

## 🛠️ Команди для адміністраторів

### Моніторинг

```
/статус - показує статус системи
/логи останні:10 - показує останні 10 записів логів
/безпека інциденти - показує останні інциденти безпеки
```

### Управління безпекою

```
/безпека блокувати користувач:ID - блокує користувача
/безпека розблокувати користувач:ID - розблоковує користувача
/безпека ліміти скинути - скидає ліміти для всіх користувачів
```

## 🔧 Оновлення безпеки

### Регулярні перевірки

**Щотижня**:
- Перегляд логів безпеки
- Аналіз метрик
- Оновлення залежностей

**Щомісяця**:
- Аудит прав доступу
- Перевірка API ключів
- Тестування системи безпеки

### Ротація ключів

Рекомендується регулярно ротувати API ключі:
1. Створити новий ключ у відповідному сервісі
2. Оновити `.env` файл
3. Перезапустити бота
4. Видалити старий ключ

## 🦙 Локальний AI та конфіденційність

### Переваги локального AI (Ollama)

- Дані не залишають інфраструктуру
- Відсутність обмежень API ключів
- Можливість офлайн-роботи

### Налаштування

За замовчуванням AI обробка виконується локально через Ollama:
- Дані (запити, контекст RAG, результати) не покидають хост
- Зовнішні провайдери (OpenAI/Anthropic) вмикаються лише за явної конфігурації
